# LLM Wiki 建立前的需求討論紀錄

> 依課堂「先討論、後生成」流程：先讓 AI 訪談釐清需求，整理成需求摘要，
> 經使用者確認後才生成 `AGENTS.md` 與資料夾結構。
> 討論日期：2026-11-16

## 訪談問答（AI 提問 → 使用者回答）

| # | AI 的問題 | 使用者的回答 |
|---|---|---|
| 1 | 這個 Wiki 主要給誰看？ | 不熟悉 LLM Wiki 的同學與助教；之後簡報也以他們為對象 |
| 2 | 主題範圍？ | Karpathy 的 LLM Wiki 模式本身：核心觀念、操作、和 RAG 的差異、真實實作案例 |
| 3 | 要哪些頁面類型？ | 綜述（overview）、概念頁（concept）、實體頁（entity：專案與工具）、比較頁（comparison）、來源摘要頁（source）、綜合分析頁（synthesis） |
| 4 | 用什麼語言？ | 台灣習慣的繁體中文；專案名稱與技術名詞保留英文原文 |
| 5 | 出處要多細？ | 每一頁至少標出依據的 raw 來源；關鍵數字（如百分比）逐句標 |
| 6 | 資料互相矛盾怎麼辦？ | 並列保留、標注各自來源與差異原因，不擅自刪改或硬統一 |
| 7 | 一次 ingest 一篇還是批次？ | 一次一篇：每篇 ingest 完立刻跑 lint 小圈、記 log、git commit |
| 8 | 之後要產出什麼？ | 一份教學 HTML 簡報（8–15 頁），內容只能用 wiki，每頁標出處 |
| 9 | lint 要檢查什麼？ | 斷連結（[[link]] 沒有對應頁）、孤兒頁（沒人連進來）、缺出處的頁、index.md 沒收錄的頁 |

## 需求摘要（經使用者確認）

1. **主題**：LLM Wiki（Karpathy 2026-04 提出的個人知識庫模式）
2. **讀者**：不熟悉主題的同學與助教 → 內容要能獨立閱讀、名詞要有解釋
3. **結構**：`raw/`（不可修改的來源）＋ `wiki/`（LLM 維護的頁面）＋ `AGENTS.md`（schema，維護規則）
4. **頁面類型**：overview / concept / entity / comparison / source / synthesis，正反引用都用 `[[頁面名]]`，出處標 `raw/` 檔名
5. **語言**：台灣繁體中文
6. **矛盾處理**：並列保留、不硬統一
7. **Ingest 節奏**：一次一篇，ingest → lint → log → commit（小圈快轉）
8. **下游產出**：教學 HTML 簡報，只能引用 wiki 頁面、每頁標出處、8–15 頁、渲染後不得溢出
9. **Lint 項目**：斷連結 / 孤兒頁 / 缺出處 / index 未收錄

確認後，AI 依此摘要生成 `AGENTS.md` 並逐條對照檢查（摘要裡的每一條都寫進手冊）。
